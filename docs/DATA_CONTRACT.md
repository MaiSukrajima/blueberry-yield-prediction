## 1. 数据来源与核验

### 1.1 为什么不是原计划的竞赛数据

原选题 `DeepBlueberry Challenge 2025`（Kaggle 竞赛）是**邀请制竞赛**，数据接口需要认证，
非受邀参赛者无权下载。因此改用 Kaggle **Datasets** 板块同主题的公开数据集。

**这不影响作业要求**：任务类型（用环境/生物/气候特征回归预测 `yield`）、
特征集合（16 列）、评估指标（MAE）全部一致。

### 1.2 数据从哪来

| 层 | 内容 | 证据 |
| --- | --- | --- |
| **① 学术源头** | Obsie, Qu, Drummond (2020)《Wild blueberry yield prediction using a combination of computer simulation and machine learning algorithms》。缅因大学用蓝莓授粉模拟模型运行仿真，聚合成 **777 条**记录 | Mendeley Data，DOI `10.17632/p5hvjzsvn8.1`，CC BY 4.0 |
| **② 公开发布** | Kaggle Datasets 两个**独立上传者**都收录了这份 777 行 CSV | `saurabhshahane/wild-blueberry-yield-prediction`（附 Data in Brief 官方说明文档）、`shashwatwork/wild-blueberry-yield-prediction-dataset` |
| **③ 本地落地** | `data/raw/WildBlueberryPollinationSimulationData.csv` | md5 `feffa3af1cbb3c8860f4ae34241adc3d`，85,259 字节 |

**获取方式：无需账号、无需 API Token、无需人工下载。**

```bash
python src/data/fetch_dataset.py
```

背后调用的是 Kaggle Datasets 的公开端点：

```
GET https://www.kaggle.com/api/v1/datasets/download/{owner}/{dataset}
```

实测该端点对公开数据集不要求认证，直接返回 zip。
**两个不同上传者的 zip 内那份 CSV 的 md5 完全相同** —— 这是数据未被篡改最硬的证据
（两个互不相干的用户不可能上传出逐字节相同的伪造文件）。

### 1.3 核验结论

运行 `python src/data/validate_data.py`，结果 **13 通过 / 3 警告 / 0 失败**。

| 核验项 | 实测 | 判定 |
| --- | --- | --- |
| 规模 | **777 行 × 18 列** | 与数据集声明一致 |
| 缺失值 | 0 | 通过 |
| 完全重复行 | 0 | 通过 |
| 列类型 | 18 列全数值型 | 无需类别编码 |
| `yield` | min 1637.704022 / max 8969.401842 | 与学术原件精确一致 |
| `yield` 分布 | mean 6012.8482 / std 1356.9553 | — |
| 常量列 | 无 | 16 特征全部有信息量 |

**三条必须在建模前知道的警告**（不阻塞，但决定方案选择）：

1. **`fruitset` 与 `yield` 的 Pearson r = 0.9841**，`seeds` 0.9612，`fruitmass` 0.9304。
   三者共同解释了产量绝大部分方差 —— **本数据的信号高度集中在果实类特征上**。
2. **温度六列近乎完全共线**（最高 |r| = 0.9999）。它们几乎是同一信息的六种表达。
3. **各特征极差相差 147 倍**（`clonesize` 10–40，`honeybee` 0–18.43，`RainingDays` 1–34）。
   线性模型与神经网络**必须先标准化**，否则结果被大量纲特征主导。

### 1.4 关于 `Row#`

| 项目 | 实测 |
| --- | --- |
| 取值 | `0..776` 连续整数 |
| 唯一值 | 777 个 = 行数 |
| 含义 | **就是原始行号**，一一对应每一行 |

**结论：`Row#` 不能入模。** 理由很直接——它唯一对应每一行，等于给模型发了一张
「这是第几号样本」的身份证。在训练集里它可能学不到有用规律，但一旦模型以任何形式
记住它（树模型的切分、KNN 的距离），验证集上就会给出虚假的高分。

**与 v1.x 的重大差异**：v1.x 里 `Row#` 是"分组标签"（776 个值重复 14,224 次，结构上确有分组）；
本版里它退化为纯行号，**不再有组结构问题，也不再需要 GroupKFold 的讨论**。

**一处更正（v2.1）**：v1.x 曾据此推断"`Row#` 会造成数据泄漏"。实测在 v1.x 数据上，
随机 5 折 MAE 为 274.87、按 `Row#` 分组 5 折为 274.79，相差 0.03%；
把 `Row#` 直接作为特征入模，MAE 也只从 274.87 变为 274.95。
结论：**组结构存在，但未产生实质泄漏**。
"不能入模"的判断仍然成立，只是理由应当更正为——它只是样本序号，没有生物学含义，
且无法对样本外数据使用；而不是"会造成泄漏"。

### 2.1 两个必须纠正的误解

1. **没有类别变量。** 18 列全为数值，分工表里「类别编码」这一项**不适用**，可以省掉。

   但 `Row#` 同样**只做对齐、不做特征**。

## 4. 切分规则（本约定的核心）

### 4.1 为什么统一切分

8 个人各切各的 8:2 → 验证集样本不同 → **分数不可比**，A 的 98.2 和 B 的 101.5 谁更好说不清；
而且 6 个人反复在同一个验证集上调参 → 验证集被"调穿"，报告分数虚高，holdout 一测就崩。

### 4.2 L1 开发评估层：固定 5 折交叉验证

| 参数 | 取值 |
| --- | --- |
| 折数 | `n_splits = 5` |
| 打乱 | `shuffle = True` |
| 随机种子 | `random_state = 42`（全项目唯一种子，不得自改） |
| 分层策略 | 按 `yield` 十等分箱分层（`qcut(q=10)` + `StratifiedKFold`） |
| 作用范围 | 仅 CV 区的 621 行 |
| 每折大小 | 验证 124–125 行，训练约 496 行 |

**指标口径（重要）**：报 **OOF MAE** —— 把 5 折验证预测拼成完整一列（621 个预测），
再整体算一次 MAE。**不要**报 5 个 MAE 的算术平均。
同时报每折 MAE 的均值 ± 标准差，用来看模型稳定性。

> ⚠️ **每折验证只有 124 行**。这意味着折间波动天然偏大（实测基线的折标准差在 6–9 之间）。
> **比较两个模型时，差距小于约 5（即 5% 左右）基本不可信**，不要在小数点后两位上做文章。

### 4.3 L2 终检层：冻结 Holdout

| 参数 | 取值 |
| --- | --- |
| 规模 | 156 行（20%） |
| 生成方式 | 切分前用 `train_test_split(test_size=0.20, stratify=yield 分箱, random_state=42)` 抽出 |
| 使用规则 | **每人最多 3 次**，用一次记一次，写进 `reports/holdout_usage.md` |
| 允许行为 | 最终定模后评估一次 |
| 禁止行为 | 早停、调参、模型选择、特征筛选 |

### 4.4 提交阶段的训练口径

1. **选参**：用 L1 的 5 折 OOF MAE 选模型与超参；
2. **终检**：用 L2 holdout 确认一次；
3. **全量重训**：用**全部 777 行**（含 holdout）按选定超参重训。

第 3 步最容易做错：很多人拿 621 行训完就交，白扔 20% 数据。

### 4.4.1 基线门槛（已实测，可直接复现）

运行 `python src/data/baselines.py`：

| 模型 | OOF MAE | 每折均值 ± 标准差 | 相对常数基线 |
| --- | --- | --- | --- |
| 常数基线（训练折均值） | 1103.77 | 1103.79 ± 8.88 | — |
| **Ridge（StandardScaler, alpha=1）** | **98.79** | 98.78 ± 6.58 | **−91.1%** |
| RandomForest（默认, 100 棵） | 123.14 | 123.12 ± 8.54 | −88.8% |
| HistGradientBoosting（默认） | 116.49 | 116.49 ± 8.15 | −89.4% |

**三条判据：**

1. **低于 1103.77** 才算模型学到了东西（废话级门槛，但必须过）。
2. **低于 98.79** 才算超过线性模型。
3. **注意一个反直觉现象**：Ridge（98.79）**明显优于**树模型（116–123）。
   原因有二 —— ① `fruitset` 与 `yield` 近似线性（r=0.984），线性模型已能吃掉主要信号；
   ② 训练集只有 496 行，树模型容易过拟合小样本。
   **这不是你的模型写错了，是数据的性质。** 想超过 98.79 需要真正动特征工程，
   而不是换个更复杂的模型。

参考：`yield` 均值 6012.85、标准差 1356.96，所以常数基线的 MAE/均值 ≈ 18.4%。

## 6. 使用注意事项（红线）

### 6.1 七条数据泄漏红线

1. **预处理必须在折内 fit。** 标准化、归一化、缺失填充、编码——所有 `fit` 只能看到当折训练集。用 `sklearn.pipeline.Pipeline` 强制，不要手写。
2. **禁止用 holdout 的任何统计量。** 包括用它的均值/方差做标准化。
3. **禁止用 `yield` 构造特征。** 包括 groupby 均值编码、目标编码、按 yield 排序的排名特征。
4. **`Row#` 不入模。** 可用特征只有 `EXPECTED_FEATURES` 里的 16 列。
5. **holdout 不参与任何决策。** 不许早停、调参、选模型、特征筛选。
6. **数据增强样本不得跨折。** 合成样本只能在其所属折的训练集内。
7. **禁止把 CV 区数据伪装成无标签数据做伪标签。** 除非报告里明确声明。

### 6.2 数值处理约定

- **目标变换**：默认**不做变换**，直接在原始尺度回归，损失用 `L1Loss`（与 MAE 对齐）。
  若坚持用 `log(y)`，必须注明，且**所有指标必须反变换回原始尺度**再算 MAE。
- **标准化**：线性模型与神经网络**必做**（量纲差 147 倍）。树模型不需要。
- **温度六列共线**：可考虑合并为 1–2 个主成分，或直接交给正则化模型。
  若做列筛选，必须在报告里说明依据，且**全组用同一套特征**（否则分数不可比）。
- **`fruitset` 极强**：它几乎单独决定了产量。不要因为它"太强"就删掉——
  它是真实的生物学指标，不是泄漏。但报告中应说明产量主要由坐果率驱动。

4. 训练 / 推理耗时
